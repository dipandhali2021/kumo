# Version 1.4 — wallpaper collection and background rotation

Version 1.4.0 / versionCode 5. Adds Wallpapers as a fourth tab. Existing CI workflow unchanged. Prior features remain.

## Current lock-screen background
Import current lock-screen wallpaper is an explicit action. On Android 12 and older it requests READ_EXTERNAL_STORAGE and reads the static lock file (or shared system wallpaper if no separate lock image). OEM policies/live wallpapers can block this. On Android 13+, normal access to another app's wallpaper is blocked. No all-files permission or silent screenshot workaround is used; Choose original photo uses Photo Picker instead.

When the current wallpaper ID matches a saved Kotoba Wall last-applied ID, the clean background is reused, preventing old vocabulary from being flattened underneath new text. This requires a successful apply by v1.4; older versions did not record the ID. Android's clock is not part of the image. External imported images may already have baked-in text; choose an original image if needed.

## Free photo browsing
https://picsum.photos/ supplies a public no-key curated feed (images from Unsplash), with 12 photos/page and photographer/source links. Save & preview stores a source-aspect image and opens Studio. Coil 2.7.0 loads thumbnails with explicit loading/error states. Image fetches are bounded and redirects restricted to HTTPS Picsum/Fastly. Browsing/saving discloses normal IP/network metadata to the provider/CDN; own photos are not uploaded. This is not keyword wallpaper search. Review image/provider licensing before publishing a commercial catalog. Coil: Apache 2.0.

## Static or screen-off rotation
Keep chosen wallpaper static is default: only vocabulary changes. Save at least two backgrounds to enable Rotate saved wallpapers + words, then enable screen-off updates in Schedule. Both change on accepted screen-off events. Background rotation is sequential through saved images, with no internet download on every wake. Timed updates continue to advance words only. Rapid toggles can be coalesced; Android/OEM restrictions remain.

## Persistence
Photo Picker imports/API selections appear in a private collection (12-entry and storage limits). Remove requires confirmation and cannot remove the active image. Applying a wallpaper stores a separate clean Last used background with palette/crop metadata. It survives restart and does not contain vocabulary. A clean copy is only refreshed when background/crop changes. Restore reuses a source entry if available. Uninstall/clear-data removes storage; this is not cloud backup.

## Display sizes
Source images are cropped, not stretched. Output follows native physical-display proportions, bounded within 2160x3840 and roughly four megapixels. Preview refreshes on configuration-size changes. Portrait phones, tablets and foldables share the renderer; OEM crop behavior, lock-screen rotation and fold states still need device tests. No guarantee of identical results on every screen/device.

## Validation and acceptance
Static source checks only in generation. Android build/lint, JVM/device tests, actual UI/font/image inspection, live downloads and wallpaper permission behavior were not verified (no SDK/emulator/reachable network). Check CI, then test the phone. New tests cover API parsing/URL bounds, source URL handling, collection rotation and default static mode.

Test import on API24–32 with permission granted/denied; live wallpaper handling; modern-Android fallback and own-background reuse; browsing/saving/removing/restore offline; static and two-background screen-off rotation with JLPT filters; app restart; no old words in Last used; fold/rotate behavior; HTTP errors/full collection/low storage. Preserve data before uninstalling for a debug-signature mismatch.
