# Kumo 1.10.0

## New application ID

Kumo now installs as `com.kumo.app`. It previously installed as `com.kotobawall.app`.

- Package, application ID, namespace and source layout renamed to `com.kumo.app`.
- `KotobaApplication`, `KotobaTheme` and `KotobaApp` are now `KumoApplication`, `KumoTheme` and `KumoApp`; the platform theme is `Theme.Kumo`.
- WorkManager job name, the Pexels keystore alias, the wake-lock tag, the outgoing User-Agent strings, the Gradle bootstrap cache directory and the debug artifact name were renamed to match.
- Release signing uses a new Kumo production key, valid until 2054-02-12.

### What this means when you upgrade

Android treats this as a **different app**. Kumo installs alongside the old `com.kotobawall.app` instead of updating it in place, so:

- You will see two icons until you uninstall the old app.
- Saved photos, the vocabulary collection, settings and the on-device Pexels key do **not** carry over. The Pexels key must be entered again.
- Uninstalling the old app does not affect the new one, but it does delete the old app's data.

Install Kumo 1.10.0, confirm it works and that you have your Pexels key back, then uninstall `com.kotobawall.app`.

Updates from 1.10.0 onward keep your data, as long as they are signed with the same key.

## Signing

- A new production signing key was generated for `com.kumo.app`. The keystore, alias and passwords are held offline and are not in this repository.
- The previous identity was signed by a different key, so it cannot be updated in place regardless of key choice.
- `docs/PRODUCTION_RELEASE.md` documents the key, the four Actions secrets and the release run.
