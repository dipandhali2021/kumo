# Kotoba Wall 1.5 — Pexels discovery and focused Studio

- Pexels is the default source; the existing Unsplash-via-Picsum catalogue is second.
- Featured uses the Pexels curated feed. Search supports keywords and portrait/landscape/square/any filters. Shape filters do not apply to Featured.
- Topic shortcuts: Minimal, Night city, Space, Architecture, Ocean and Textures. They are editable searches, not promises about catalogue content.
- Picsum remains browse-only: its API does not offer keyword search.
- Wallpapers opens on Discover, with Saved and My background sections for quick access. The source selector and search live in Discover. Photo selection, gradients and vertical crop controls have been removed from Studio and consolidated in Wallpapers.
- Existing saved backgrounds, Last used, static mode and offline screen-off rotation are preserved. New photos from either source use the same saved collection.

## Credentials and privacy

Enter a Pexels API key in Wallpapers → Pexels → Add Pexels API key. The supplied chat credential is intentionally not embedded in source, CI configuration or the APK. Rotate a key shared in chat before distribution. For a public app serving many users with a developer-owned key, use a separately authenticated/rate-limited backend instead of embedding a shared key.

On-device keys use AES-GCM with an Android Keystore key; ciphertext lives in noBackupFilesDir. The existing manifest also disables app backup. The UI never pre-fills a stored key or saves the key input into Android saved-instance state. Manage lets users replace/remove it. Removing app data or uninstalling removes the credential and saved collection. Device compromise/root can defeat client-side protections.

Only api.pexels.com receives the Authorization header. API redirects are refused, and response pagination URLs are not followed. Thumbnails/downloads from images.pexels.com are unauthenticated. Requests have timeouts and bounded responses. Pexels receives search terms, key and network metadata; providers/CDNs receive image requests. Personal photos are never uploaded.

Up to 24 browse pages are cached in memory for 24 hours, cleared on key changes and process death. Searching is explicit, not per keystroke. HTTP 401/403 and 429 have actionable messages; there is no rate-limit bypass. Rotation does not make API requests.

## Pexels usage and attribution

This is a Japanese-learning app with a supporting background picker, not a standalone stock-photo gallery. Pexels explicitly allows this supporting-feature use, while disallowing apps that replicate its service. Reassess permission with Pexels before distributing a gallery-first product. Provider and photographer links are displayed in the selection flow and photo-source metadata is saved with downloaded backgrounds.

## Validation

Source-level checks only in the development sandbox. Added JVM tests for URL encoding, curated/search orientation behavior, hostile URLs, invalid sizes, pagination and key-header validation. Android build, lint, unit/instrumentation execution, API access, Keystore behavior and visual/device behavior require CI/device verification. No successful test/build claim is implied by the presence of tests.

Device checklist: install over the previous app with the same signing key; check existing collection and Last used; add/replace/remove a key; reopen after process death; try Featured/search/topics/shapes/pagination; test key rejection, rate limit and offline errors; save a photo from each source; check attribution; verify Studio has no Background block; change gradients/crop in Wallpapers; apply and test static/rotating screen-off modes; inspect portrait/landscape/foldable layouts. The existing legacy-wallpaper lint compatibility helper is unchanged.
