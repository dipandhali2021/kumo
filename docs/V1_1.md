# Version 1.1 — pinned preview and screen-off updates

## New editing experience

- Wallpaper preview stays pinned while controls scroll independently.
- Text position, size and panel opacity update during dragging; settings persist on release.
- Preview and export share the Android Canvas text renderer. Background images are decoded only for background/crop changes, not every text-slider event.
- Expand the preview for a larger view with a position slider. The clock guide can be hidden and is never saved in the wallpaper.
- Landscape layout puts controls beside the preview. Apply stays visible.

## Enable screen-off updates

1. Install the new APK and choose your background/layout.
2. Open Schedule and tap Enable screen-off updates.
3. Confirm and allow notifications on Android 13+.
4. Check that Active and the ongoing Kotoba Wall notification appear.
5. Turn the screen off, leave it off for a few seconds, then wake it. The next word should appear on supported devices while the service remains active.
6. Stop from the app or the notification's Stop updates action.

This is opt-in and off by default. It listens for screen-OFF, not unlock or a strict lock-state transition; display timeout can also trigger an update. It uses a foreground service, not an accessibility service or overlay. Foreground-service, notification and bounded wake-lock permissions are declared. The wake lock lasts at most 15 seconds for each accepted render; no indefinite wake lock or continuous rendering loop is used.

Screen-off mode and timed rotation are alternatives; enabling either disables the other. Rotation uses all bundled words and preserves the original image.

## Limits

- Android/OEM restrictions, force-stop, reboot and rapid toggles may delay or prevent a change. This is best effort, not a guarantee at every wake.
- Toggles during an in-flight render are coalesced, not queued. An already executing wallpaper write may finish just before Stop takes effect.
- Android may restart a sticky service after process death, but this is not guaranteed. After force-stop/reboot, open the app and tap Resume when offered. No boot-time automatic start is implemented.
- The notification is intentionally visible. If notification/channel access is blocked, the app explains that it must be enabled. On some Android versions dismissing an ongoing notification does not stop its service; use Stop updates.
- Android 14+ uses the declared specialUse foreground-service type. This is a sideload/test implementation, not a claim of Google Play approval. Publishing requires review of this use case.
- Automatic updates use the latest saved layout. Dragging without releasing does not persist a setting.
- If you wake the screen before rendering/application finishes, the previous word may still be visible briefly. No always-on-display integration is included.

## Validation

Version 1.1 received static source, XML/resource and configuration checks only. Android compilation, actual Compose visual QA and service behavior remain unverified in the generation sandbox. Consult GitHub Actions for assembleDebug, unit test and lint results. The new instrumented preview/export comparison test requires an emulator/device and is not run by the current workflow.

Required device checks: portrait/landscape/expanded sliders, notification grant/denial/blocked channel, app and notification Stop, resume after force-stop/reboot, screen timeout and power-button off events, rapid toggles, battery restrictions, missing photo and wallpaper-policy errors, and API 24 plus Android 14+ behavior.

## Installing the debug update

Version 1.1.0 has versionCode 2. Install over the old app if signatures match. GitHub hosted runners can generate different debug signing keys between builds. If Android reports a signature conflict, uninstalling the old app permits installation but deletes saved photo/settings; export anything needed first. Stable signing is a separate setup; never commit a keystore or password.
